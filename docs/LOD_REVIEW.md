# Distant Terrain Review

Research date: 2026-10-19. Follow-up implementation: 2026-10-20. Scope: the local Voxy 0.2.19 beta and Distant Horizons 3.3.4 for 26.3 binaries, and Aervium's current Phase 6 working tree. This is an inspection of those versions, not a claim about later releases. No game or comparative benchmark was run for this review.

## Voxy

Paths in this section are under `me/cortex/voxy/` unless an asset path is given.

| Area | Observed behavior and evidence |
|---|---|
| Unvisited seed terrain | No built-in distant seed generation was found in this binary. `commonImpl/importers/WorldImporter.java` reads existing chunks; `commonImpl/mixin/chunky/MixinFabricWorld.java` captures chunks produced by an external pregenerator. `commonImpl/WorldIdentifier.java` uses world identity/seed for cache separation, which is not terrain generation. Therefore there are no independent noise, surface or feature generation stages or generated chunk saves to attribute to Voxy itself. |
| Visited data | `common/world/service/VoxelIngestService.java` queues chunk sections and copies their sky/block light layers for service processing; `common/voxelization/WorldConversionFactory.java` converts block states, biomes and light; `common/world/WorldUpdater.java` propagates the hierarchy. This retains real blocks including trees and overhangs. |
| Existing region files | `commonImpl/importers/WorldImporter.java` scans region headers and chunk stream compression, decodes NBT section palettes and light, and submits voxel conversion without loading game chunks or creating chunk tickets. It also imports zipped region directories. In this version external chunk streams are rejected. Imports are asynchronous and wait when the outstanding chunk count exceeds 10,000. |
| Representation | `common/world/WorldSection.java` holds 32 cubed cells in a 32,768-element `long[]`, with X contiguous, then Z, then Y: 256 KiB for the cell array before overhead. `common/world/other/Mapper.java` packs a block-state mapping ID (20 bits), biome mapping ID (9 bits) and sky/block light (8 bits) into each cell. This is a volume, not one height per column. `common/voxelization/WorldVoxilizedSectionMipper.java` builds coarser voxels. Full vertical geometry is possible, at a much larger cost than Aervium's heightfield. |
| Persistence/compression | `common/world/SaveLoadSystem3.java` serializes a section key, metadata, 32,768 short palette indices and a long-valued palette; mapped block/biome identities are stored separately. `common/StorageConfigUtil.java` selects a section serializer over a compression adapter over RocksDB by default, with Zstandard level 1. `common/config/storage/` also contains LMDB, memory and other optional backends; `common/config/compressors/` includes LZ4. `common/world/ActiveSectionTracker.java` manages residency rather than retaining every decoded section forever. |
| LOD selection and culling | `client/core/rendering/hierachical/NodeManager.java`, `AsyncNodeManager.java` and `assets/voxy/shaders/lod/hierarchical/traversal_dev.comp` maintain/traverse a spatial hierarchy, using projected size and subdivision settings. `assets/voxy/shaders/lod/frustum.glsl`, `assets/voxy/shaders/hiz/hiz.comp` and the `lod/gl46/cull/` shaders support GPU visibility/depth culling. This is much more than Aervium's horizontal distance test. |
| Transitions | The hierarchy coordinates parent/child availability. `client/core/rendering/building/RenderDataFactory.java` obtains neighboring section faces and creates boundary geometry; this is volumetric neighbor meshing, not Aervium's fixed heightfield skirt. `client/core/NormalRenderPipeline.java` and `assets/voxy/shaders/post/blit_texture_depth_cutout.frag` composite distant color/depth against real terrain, with selectable fog/fade. A universal claim of morphing or a particular dithering algorithm is not justified by those paths alone. |
| Meshing and vertices | `RenderDataFactory.java` and `client/core/util/ScanMesher2D.java` merge compatible faces into rectangles. Each resulting quad occupies one packed 64-bit record; `assets/voxy/shaders/lod/quad_format.glsl` and `lod/gl46/quads3.vert` decode it and reconstruct corners. This is 8 bytes per quad record, not 8 bytes per conventional vertex. Model data lives separately. |
| GPU storage/draws/uploads | `client/core/rendering/section/geometry/BasicSectionGeometryManager.java` places sections in a shared geometry allocation with section metadata, rather than one GPU object per tile. `client/core/rendering/section/backend/mdic/MDICSectionRenderer.java` and `lod/gl46/cmdgen.comp` implement indirect rendering. `AsyncNodeManager.java` limits a geometry-update batch by count, available geometry space and approximately 1,024,000 estimated upload bytes. These are implementation budgets, not a time guarantee. |
| Lighting, water and color | `client/core/model/` prepares model/material information; `lod/block_model.glsl` and `lod/lighting.glsl` reconstruct appearance using block identity, biome and light. The renderer has distinct translucent handling (`lod/gl46/buildtranslucents.comp`), fog/fade composition and optional screen-space ambient occlusion (`client/core/SSAO.java`). Water retains a fluid/material identity instead of becoming an opaque blue heightfield. |
| Actual controls | `client/config/VoxyConfig.java`: enabled/rendering/ingestion are distinct switches; `sectionRenderDistance` changes coverage in units of 512 blocks (default 16 means 8,192 blocks); `subDivisionSize` changes the projected subdivision threshold, hence geometry/residency; `serviceThreads` changes shared service concurrency; `dontUseSodiumBuilderThreads` changes builder scheduling; fog mode chooses fog/fade combinations; SSAO mode controls the additional screen-space pass. `client/core/rendering/hierachical/HierarchicalOcclusionTraverser.java` squares the subdivision size for its area threshold; `client/core/VoxyRenderSystem.java` can adjust it under geometry pressure. `common/thread/UnifiedServiceThreadPool.java` schedules services. Minimum priority alone is not a CPU duty-cycle cap, and no DH-style duty-cycle setting is exposed here. |

This binary has native RenderPearl support as well as OpenGL: `common/wrappers/DependencySetup.java` chooses the renderer definition. `core/render/renderer/FogRenderParamFactory.java` builds far/height fog controls; color source, start/end, density/falloff and height mixing are configurable. Transparency, ambient occlusion, tint/brightness/saturation and textures add quality and GPU work beyond Aervium's opaque RGB surfaces. |

Actual quality and CPU controls (`core/config/Config.java`, `core/config/eventHandlers/presets/RenderQualityPresetConfigEventHandler.java`, `ThreadPresetConfigEventHandler.java`):

- Horizontal quality moves detail drop distances; maximum horizontal resolution sets the finest cell width. Vertical quality limits retained render layers. These affect geometry and memory, rather than generation thread count.
- Distance sets area coverage. Transparency, textures, ambient occlusion, fog and noise settings affect render appearance and passes. Brightness/saturation alter resolved color, not the seed.
- World compression chooses strict block changes versus visually equivalent changes (including ignoring hidden interior changes). File compression chooses a storage codec. Neither is the horizontal quality setting.
- Thread presets select roughly 10%, 25%, 50%, 75% or 100% of available processors; minimal impact also uses a 0.5 run-time ratio. Custom count and run-time ratio permit independent concurrency and duty-cycle control.
- Generation plan and target stage determine whether the rough surface, real terrain, decoration or full server generation runs. Pre-existing-only behavior cannot create trees in an unsaved chunk.

The quality presets concretely combine those controls: Minimum uses two-block horizontal resolution, one vertical layer, no transparency/SSAO/anti-aliasing/fade; Low uses block resolution, Low vertical/horizontal quality, no transparency/SSAO and single-pass real-terrain fade; Medium and higher enable transparency, SSAO and double-pass fade with increasing horizontal/vertical detail. Low and higher enable anti-aliasing and LOD dithering. Biome blending increases from zero to one to three; the high presets disable cave culling. `api/enums/config/EDhApiVerticalQuality.java` gives the finest-level layer budgets as 1 (height map), 4 (Low), 6 (Medium), 16 (High), 32 (Very High), 64 (Extreme) and 512 (Pixel Art), decreasing at distance. These are render-layer budgets, not a promise to retain every full-data run in the mesh.

## Aervium gap analysis

The baseline paths are `src/main/java/com/aryston/aervium/core/lod/`, `client/lod/`, the three distant-terrain mixins, `client/config/`, `config/AerviumConfig.java` and `src/main/resources/assets/aervium/shaders/lod/`.

| Topic | Baseline and implication |
|---|---|
| Strength: bounded representation | A 64 by 64 `LodTile` has 32 KiB of packed samples, versus 256 KiB for one decoded Voxy 32-cube voxel array. Coverage and represented geometry differ, so this is not an equal-quality memory benchmark. The fixed one-surface format is inherently cheap. |
| Strength: integration | Native 26.3 RenderPearl/Vulkan draws and an optional Helion geometry-buffer hook share normal frame ownership. Aervium needs no separate renderer dependency. This is an integration advantage over Voxy's renderer-specific path, not an exclusive capability over DH, whose inspected binary also supports RenderPearl. |
| Strength: seed preview | Sparse `getBaseHeight` plus biome colors provides independent coarse coverage without creating/saving chunks. It is useful before exact data arrives, and Voxy itself has no equivalent seed generator in the inspected binary. |
| Missing real generation | `GeneratedColumns` interpolates ocean-floor height and applies categorical biome color plus a uniform five-block forest lift. It does not run terrain surface rules, structures or features. Trees and real materials cannot be recovered from that approximation. |
| Missing sources/cache | Only current-session client chunks are captured. Saved worlds are ignored and there is no persistent LOD cache. Repeated visits/games redo work and lose player builds outside the view. |
| Representation/appearance | One RGB surface cannot represent overhangs, layered foliage, cliff material changes or light values. `ColumnSampler` uses tint directly or map color, not texture-average albedo. Water is opaque and the forward shader is effectively fullbright. Helion receives full sky light and a derived normal, but side shading is already baked into RGB. |
| Coverage bugs | A populated tile is not necessarily complete. Sparse child data can overwrite a broader seed cell, and a partially populated child can trigger a split. Provenance and footprint completeness must be distinct. |
| Work/residency | A count of six uploads does not bound bytes/time. The ready queue and store can grow; old generation can occupy workers after a world change; failed requests can remain permanently suppressed. Priority is not CPU throttling. |
| Mesh/draw cost | Every present cell emits a top quad, even across a flat uniform lake; every tile has its own draw/buffer. Fixed edge skirts do not adapt to larger inter-level height differences. No LOD-specific frustum or GPU occlusion path exists. |
| Transitions | Parent/child availability is only partially coordinated; real terrain is clipped by a render-distance square rather than actual uploaded chunk coverage. Skirts hide some cracks but there is no geometric morph or temporal coverage fade. |

## Ranked implementation plan

The order favors independently testable correctness and bounded work before increasing source fidelity. Expected impacts are hypotheses, except for exact byte/quad counts in unit fixtures. Matching both references while beating both on all resources remains a target, not a demonstrated result.

| Rank | Change | Expected visual effect | Expected resource effect |
|---|---|---|---|
| 1 | Preserve provenance and complete footprints; hold coarse coverage until children are complete and uploaded | Prevent sparse replacements and early splits from cutting holes in the horizon | Small flag/counter cost; no larger sample |
| 2 | Merge equal top rectangles and wall runs; bound ready meshes and per-frame upload bytes/time | Identical retained surfaces; faster convergence without upload bursts | Large vertex reduction on flat areas; bounded backlog; uneven terrain gains less |
| 3 | Read saved chunk section palettes through vanilla asynchronous storage, resolve their real top blocks/biomes, prefer these over the seed preview | Actual saved trees, builds and surface materials beyond the current view in single player | More bounded background I/O/decoding; avoid server chunk tickets and generation; retain the cheap far preview |
| 4 | Cancel stale generation within tiles, recover failed requests, throttle Low/Balanced and bound sample residency | Fewer stale replacements and missing tiles after setting/world changes | Less wasted CPU, controlled duty cycle and memory; deliberately slower fill on Low |
| 5 | Neighbor-aware edge skirts and changed-border remeshing | Hide cracks larger than the fixed skirt at mixed detail boundaries | Small boundary work on the store worker; no extra vertex format |
| 6 | Isolated original 26.3 terrain/feature generation with dependency neighborhoods and a persistent versioned cache | Real seeded surface blocks, structures and trees in never-saved land | Significant CPU initially; amortize via cache, coarse preview and near-first exact refinement |
| 7 | Optional capped vertical spans near the transition; retain cheap single surfaces far away | Cheap overhangs, separated canopy/ground and cliff materials | Extra bytes only where needed; must measure span limits against quality |
| 8 | Texture-average albedo, retained light, water/material separation and forward lightmap shading | Match resource packs/day-night/water; avoid tint-only colors and baked Helion shading | Small material tables, new packed attributes and transparency cost |
| 9 | Actual real-chunk coverage mask, complementary stable transitions and geometric detail morphing | Remove clip-square holes and reduce visible popping | Requires mesh-ready chunk hooks and both draw paths; coordinate depth/shadows carefully |
| 10 | Conservative frustum bounds, pooled geometry and indirect LOD draws, then measured occlusion | Same picture with fewer submissions/invisible triangles | Lower CPU/GPU submission cost; more allocator/synchronization complexity |

## Verification and remaining work

Ranks 1 through 8 are implemented, with the bounded approximations described below. Rank 9 has uploaded-chunk masking and complementary dissolves; rank 10 has conservative frustum bounds, shared geometry and indirect draws. Vertex geomorphing and GPU occlusion are not implemented. Visual parity and resource superiority remain unmeasured.

- Sample provenance, complete footprints and known voids now survive downsampling. Complete coarse data cannot be replaced by sparse children. The selection gate uses the completeness of the **uploaded mesh**, including zero-geometry coverage, rather than the current worker tile.
- Vertices remain 16 bytes, with the former alpha byte carrying sky4/block3/water1 metadata. Equal top rectangles and side runs merge. The uniform heightfield fixture falls from 4,352 quads / 278,528 vertex bytes to 5 quads / 320 bytes. The two-layer uniform canopy/ground fixture is 12 quads, retaining its gap and underside. These are exact fixtures, not average performance claims.
- At most 24 ready meshes and 32 MiB of queued vertices plus one deferred upload are retained. Uploads stop between meshes at six meshes, 2 MiB or 1 ms. One indivisible driver call may exceed the target. Client capture checks 1 ms between columns and admits 32 copied chunks; native textures and live chunks never reach the store worker.
- Saved FULL chunks supply actual surfaces, layers, builds, biomes and sky/block light at levels 0 to 2. Saved data is tried first; complete patches avoid seed generation. Reads use `ChunkMap.read` / `SimpleRegionStorage.read` / `IOWorker.loadAsync`; `RegionFileStorage.read` opens existing files without creating missing ones. Old tags are copied and upgraded privately with dimension/generator context, never written back; future formats are ignored. Only generation workers wait, with a two-second timeout. No tickets, live chunk deserialization, entity loading or chunk saves are added.
- Complete footprints outrank incomplete ones; among equally complete samples priority is client > saved > seeded > approximate. Same-source saved refreshes are allowed and complete client edits remain authoritative. Nearby completed tiles become eligible for saved refresh after 30 seconds when missing preview work is satisfied, with first-time exact refinement taking priority. Client section dirtiness queues fresh capture. Isolated tint callbacks receive private sections and an empty engine; unsupported custom callbacks retain base colour.
- Exact seed refinement uses original private 26.3 neighborhoods: 64-block output patches, 27-square structure-start holders, 10-square biome, eight-square terrain and six-square feature regions. Structure references and required heightmaps are prepared explicitly. Terrain runs the actual combined density/surface/carver stage, followed by decoration. No LIGHT, SPAWN, live FULL conversion, entities, live POI update or chunk save runs. One exact job is permitted at a time, and its stage requests are sequential. Vanilla biome/terrain futures execute on its background executor; only the generation worker joins. Cancellation occurs between stages/chunks/rows, not within one vanilla stage.
- Exact seed support is intentionally conservative: vanilla noise/flat generator classes, with no non-vanilla block, feature-type, density-function, biome-source or structure-type registration. Other worlds retain preview plus real saved/client data. This does not sandbox arbitrary modded world generation. Low quality and distant levels retain preview heights/biome colours, including the approximate canopy offset.
- The persistent cache hashes world path, seed, dimension, serialized generator, structure option, quality, data version, separately delimited mod identifiers/versions, the frozen material palette, server JSON/structure NBT and client block textures/models/blockstates/biome colour maps. Versioned key/CRC headers protect level-1 DEFLATE payloads. Inflation, column counts and span counts are bounded. Corrupt entries are removed for regeneration; unique temporary writes publish atomically and tolerate an already-published concurrent winner on Windows. Each identity trims toward 512 MiB once per minute on writes. Mutable saved/client edits are never persisted as deterministic seed data.
- Near columns keep at most eight nonoverlapping vertical spans with 14 bytes per span plus offsets. Meshing subtracts adjacent solid intervals, emits undersides and retains opaque ground under water. Side materials sample the actual middle of the retained interval; this is a representative cliff colour, not all geological strata. A result over 65,536 layered quads falls back to the heightfield, limiting one vertex payload to 4 MiB.
- Resource-pack top/side texture averages and tint indices are copied into an immutable palette on the client in a separate 1 ms/256-state budget. An alpha-weighted linear eight-square sample grid bounds high-resolution texture cost. Workers use integers only. Actual saved/client light is retained; seed skylight is an exposed/shaded estimate, including no-sky dimensions, rather than a generated light engine. Forward shading uses the current lightmap, while Helion receives unshaded albedo and real light coordinates. Water blends without depth writes; Helion water is drawn after opaque deferred lighting through a separate optional one-target pass.
- Generation cancellation is checked within tiles and between saved reads. Request keys are released after every exit, failures have a cooldown, and old epochs cannot supply captured samples or queued/uploaded meshes after a world/quality reset. Already loaded chunks are rediscovered gradually after a reset, including multiplayer where no seed source exists.
- Both the live feature switch and restart-required module gate source/palette work. Inactive frames release GPU state once and return without rebuilding empty resource containers.
- Low targets one generator at 25% active time; Balanced targets 50% per permitted worker. High/Extreme add no idle time. These are wall-time-based targets including I/O, not a hard process-CPU percentage. At 16 logical processors the worker limits are 1 / 3 / 7 / 15. Quality retains its original split factors (1.25 / 1.5 / 2 / 2.5), finest levels (3 / 2 / 1 / 0) and height grids (8 / 16 / 16 / 32); distance buttons still only select distance and enable distant terrain.
- Once per second the store trims toward 2,048 tiles and 128 MiB including layers, favoring nearby/coarse coverage. Work between trims can temporarily exceed this. GPU geometry has eight 16 MiB pages, with coalesced suballocation and changed-range uploads. Draw instances/indirect commands use at most 32 MiB of staging, reused after zero-timeout fence checks; exhaustion defers submissions instead of waiting. Temporary generation neighborhoods, palettes, metadata and native-driver allocations are additional memory.
- Adaptive mixed-level skirts remain. Conservative frustum boxes include all retained layers and skirts. Opaque draws are batched by geometry page with indexed indirect commands; water is sorted at tile granularity. Per-draw instances carry camera-relative offsets, region bounds and complementary fade intervals, avoiding absolute-world float precision loss.
- The unconditional real-distance clip square is replaced by a 256-square R8 readiness mask: captured top-surface sections must have uploaded meshes, then coverage waits 250 ms and fades over 250 ms. Mask uploads occur at most every 25 ms. Parent/child and replaced tile meshes use complementary screen-stable 250 ms dissolves; old keys/buffers are retained until completion, and sparse previous coverage is partitioned so newly available regions are filled. This is not vertex morphing or a proof of gap-free fast flight. Model reload resets palette/cache epochs, and shutdown cancels generation and releases drawing resources without joining workers.

### Video regression repair (2026-10-20)

The supplied 12-second recording from 01:29:40 shows coarse green terrain intermittently covering more detailed terrain. The existing game log also repeatedly reports missing dungeon spawners on the distant generation worker. This is runtime evidence that the earlier compilation and engine tests did not establish correct appearance.

The audit found and repaired five independent failure mechanisms:

1. Selection depended on CPU sample residency even for complete uploaded meshes. Sample trimming could therefore remove visible detail or select a coarse parent. Selection now recognizes uploaded meshes at roots and children independently from CPU tiles. A regression test failed on the old code and passes with CPU tiles removed after upload.
2. Partial high-authority client ancestors rejected complete lower-authority previews. Complete footprints now take priority over partial ones; provenance remains authoritative among equally complete samples, preserving full client columns. A second regression test failed before the repair and now verifies complete coverage through all six levels.
3. Real-terrain masking waited for full layered capture. Chunk loads, rediscovery and uploaded sections now queue independent heightmap-only requirements, processed at most 16 columns/1 ms per frame. Mesh readiness still waits for actual required sections and verifies rotating-section coordinates.
4. Periodic saved refresh had priority over unfinished exact refinement, so a long refresh cycle could keep nearby terrain approximate indefinitely. Missing previews still run first; exact refinement now precedes refresh, and other capacity can refresh while one exact job runs.
5. Isolated features could place spawners/chests but never retrieve their block entities. Requested block entities are now retained only in private chunks, remain detached from any live level, and are removed when replaced. Nothing ticks, spawns, activates or saves them. Cache identity revision 3 prevents reuse of earlier feature output.

These mechanisms are supported by code inspection and the two reproduced engine failures; the supplied video alone does not establish the contribution of each to every flickering frame. The corrected build still needs visual confirmation in the same scene with both render paths. No game was launched during this repair.

Repair validation: `gradlew.bat build` passed with 222 tests, zero failures, errors or skipped tests, and no new warnings. This includes the two new regression tests and the coverage lifetime assertions. `bash scripts/verify.sh` passed for the workspace and all three mod repositories after correcting a documentation phrase caught by the literal word filter. The same temporary long-path/excludes settings described above were used. The corrected scene, private block entities and both render paths remain unverified in game.
